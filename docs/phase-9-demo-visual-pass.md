# Phase 9 Demo Visual Pass Notes

This document records the current Phase 9 demo scene presentation and interaction flow.

## Demo Assets

- `model.room_blockout` uses `public/models/room_blockout.glb`.
- `model.switch_wall` uses `public/models/props/switch_wall.glb`.
- `model.door_wood` uses `public/models/props/door_wood.glb` and exposes the `Open` clip.
- `model.player_spawn` uses `public/models/markers/player_spawn.glb`.
- `audio.switch_click` uses `public/audio/switch_click.wav`.

The lightweight development assets are generated by `npm run generate:dev-assets`.

## Visual Presentation

- `room_blockout_01` provides a simple floor and wall blockout so the demo reads as a room rather than isolated props.
- `switch_a`, `gate_a`, and `player_spawn_01` use distinct colors and silhouettes from the generated GLB assets.
- `trigger_gate_entry` remains a debug/editor helper displayed through the runtime AABB overlay instead of a gameplay mesh.
- The viewport smoke test verifies nonblank/varied canvas rendering and checks that timeline scrub changes canvas pixels.

## Interaction Flow

1. The player marker starts inside the room.
2. `switch_a` is interactable and gated by the `power_enabled` flag plus `gate_key` inventory state.
3. Interacting with `switch_a` queues `tl_open_gate`.
4. `tl_open_gate` samples the gate camera shot, plays the `Open` animation on `gate_a`, queues the switch sound marker, shows subtitle data, samples `Door.openAmount`, and sets `gate_a_opened`.
5. Editor timeline scrub/play now passes the active `WebRuntime` into `DirectorSystem`, so animation and camera tracks can produce visible viewport changes.

## Current Limitations

- The demo assets are generated blockout assets, not final art.
- Subtitle and sound commands are present in timeline data but do not yet have final runtime/HUD/audio output; that is Phase 10 scope.
- Showcase Mode is still planned; the current smoke path validates the authoring editor viewport.
