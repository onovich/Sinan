# Phase 8 Real Asset Runtime Notes

This document records the current Phase 8 runtime behavior for GLB/glTF assets.

## Asset Requirements

- Model assets are declared in `data/assets.manifest.json` with `type: "model"` and a URL under `public/models/**`.
- Runtime URLs use Vite public-root paths such as `/models/props/door_wood.glb`.
- Development GLB files are generated by `npm run generate:dev-assets` from `scripts/generate-dev-glb-assets.ts`.
- `model.door_wood` includes an `Open` animation clip used by `data/timelines/tl_open_gate.json`.

## Runtime Behavior

- `ThreeRuntime.loadModel()` delegates to `ThreeAssetLoader`, which uses Three.js `GLTFLoader` inside `src/runtime/three/**`.
- Loaded GLB scenes and animation clips are cached by asset id.
- `instantiateModel()` clones loaded scenes and deep-clones renderable geometry/material resources for safe per-instance disposal.
- If a model is missing, invalid, or still unavailable, runtime instantiation falls back to deterministic placeholder geometry.
- Load failures are surfaced through `console.warn` while preserving editor level loading.

## Animation Behavior

- Loaded animation clips are bound per entity through `AnimationMixer`.
- `animation.play` starts the named clip when it exists on the loaded asset.
- `animation.stop` stops the active clip or all active clips for the entity.
- `setAnimationTime` samples the named clip for timeline scrub support and leaves the action paused afterward.
- Missing clips keep the runtime state deterministic and surface a warning.

## Current Limitations

- The generated GLB files are lightweight development assets, not final art.
- The smoke test verifies real `.glb` network loads and nonblank/varied rendering; it does not yet perform visual semantic comparison against expected model silhouettes.
- Asset URL existence validation remains a later validation expansion item in the Post-MVP plan.
